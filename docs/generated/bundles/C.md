# Bundle C. Custom logic in a REST action

> Generated by `gaia-dev docs generate` from docs/dev/bundles.md. Do not edit.

<a id="overview"></a>
## Overview

Behaviour added inside an existing controller's standard action or hook (`postAction`, `getAction`, `patchAction`,
before and after hooks). It is not a new route. The issue's original wording, "custom action + route", turned out
to be the anti-pattern the reviewer rejects ([#183](https://github.com/projects4me/gaia/pull/183)). The accepted form reuses the REST verbs.

<a id="exemplar"></a>
## Exemplar

[#180](https://github.com/projects4me/gaia/pull/180) (`IssuestatusController`: colour and sort order, block deleting a status in use). Also [#198](https://github.com/projects4me/gaia/pull/198)
(`SystemnotificationrecipientController` plus a model method, mark read by entity).

<a id="touchpoints-in-order"></a>
## Touchpoints, in order

1. `app/api/v1/controllers/<X>Controller.php`: override the action or hook.
2. Optional: a model method in `app/models/<X>.php` ([#198](https://github.com/projects4me/gaia/pull/198)), or a library class under `core/libs/…` that holds the
   logic, so the controller stays thin ([#190](https://github.com/projects4me/gaia/pull/190): `TestEmailSender`, `MailerErrorMapper`).
3. Optional: metadata field changes ([#180](https://github.com/projects4me/gaia/pull/180), [#192](https://github.com/projects4me/gaia/pull/192)).
4. Bundle A: `acl.json` and `client.json` cases, harness seed rows, and an Asserter or README line if needed.
5. A unit test for the library logic.

<a id="checks"></a>
## Checks

- No new public endpoint or test-only action. Express it as a flag or field on the normal verb (reviewer on [#183](https://github.com/projects4me/gaia/pull/183);
  [#190](https://github.com/projects4me/gaia/pull/190) is the accepted shape).
- Logic that can be unit tested belongs in a class with a unit test, not only an api case (reviewer on [#183](https://github.com/projects4me/gaia/pull/183)).
- Put each dependency in the layer that owns it: SMTP settings are read inside the Mailer, not in the notification
  class (reviewer on [#183](https://github.com/projects4me/gaia/pull/183)).
- Loops over `update()` must stop on `false` and report it. Use a transaction. Don't return 200 for a partial write
  (CodeRabbit on [#198](https://github.com/projects4me/gaia/pull/198)).
- When overriding `getAction`, compare it with `RestController::getAction`. `Model::read()` returns
  `['baseModel' => rows]`, not a list, and [#199](https://github.com/projects4me/gaia/pull/199) fixed a 404 on every upload caused by `$data[0]` (4106). Check the
  stored file is readable before returning success (CodeRabbit on [#199](https://github.com/projects4me/gaia/pull/199)).
- Request overrides must not reuse stored secrets. A changed host, port or user requires the password again
  (CodeRabbit on [#190](https://github.com/projects4me/gaia/pull/190), `SmtpSettings`).
