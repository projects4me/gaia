> Generated by `gaia-dev docs generate` from docs/dev/bundles.md. Do not edit.

<a id="overview"></a>
## Overview

Every PR that changes API behaviour adds cases. A new or changed scope rule also needs harness seed rows and fixture
ids.

<a id="exemplar"></a>
## Exemplar

[#193](https://github.com/projects4me/gaia/pull/193) (full set for 4 resources). [#179](https://github.com/projects4me/gaia/pull/179) for an ACL-only rule. [#198](https://github.com/projects4me/gaia/pull/198) for client cases with a new
assertion.

<a id="touchpoints-in-order"></a>
## Touchpoints, in order

1. `T/harness/prepare-test-db.sh`:
   - add the table to the reset list (`('idea'), ('ideamessage'), …` near line 538);
   - add test-role permission rows (`atp-acl-mem-<x>-get`, `-create` for `api-test-role-acl-mem`, near line 654);
   - add seed rows, one in the member's project and one in another project
     (`INSERT … ON CONFLICT (id) DO UPDATE SET deleted = FALSE`, near line 779).
2. `T/fixtures/default.json`: `<x>Id` and `otherProject<X>Id` placeholders pointing at the seed ids
   (`api-test-<x>-NNNNNN`, same width as the sibling ids).
3. `T/apis/acl.json`: role-scoped cases. Cover member allowed, non-member denied, no permission denied, and the
   field or scope rule.
4. `T/apis/client.json`: behaviour cases, positive and negative (malformed body, validation error).
5. `T/src/Asserter.php`: only when a new assertion kind is needed ([#182](https://github.com/projects4me/gaia/pull/182), [#190](https://github.com/projects4me/gaia/pull/190), [#198](https://github.com/projects4me/gaia/pull/198), [#199](https://github.com/projects4me/gaia/pull/199)).
6. `T/README.md`: one line in the catalog when a new case family or assertion is added.

<a id="checks"></a>
## Checks

- Every new permission or scope rule gets an `acl.json` case in the same PR (pattern in [#179](https://github.com/projects4me/gaia/pull/179), [#182](https://github.com/projects4me/gaia/pull/182), [#185](https://github.com/projects4me/gaia/pull/185), [#203](https://github.com/projects4me/gaia/pull/203); the
  missing case was a follow-up on 4075). The failed [#177](https://github.com/projects4me/gaia/pull/177) → [#178](https://github.com/projects4me/gaia/pull/178) resubmission and the [#170](https://github.com/projects4me/gaia/pull/170) → [#165](https://github.com/projects4me/gaia/pull/165) follow-up came from
  ACL changes without matching cases.
- Assert the body as well as the status. Without a shape or id expectation, `Asserter::assert` does no body
  validation. Use `idsIncludes` for list scopes (CodeRabbit on [#203](https://github.com/projects4me/gaia/pull/203)), and assert body and headers for file responses
  (CodeRabbit on [#199](https://github.com/projects4me/gaia/pull/199)).
- Match each seed value to its column type: `deleted` is boolean on ideas but smallint on issues (4069, 4075). Check
  the table before writing SQL.
- A seed row that references a user must use an id that exists in every seeded DB. The harness seeds some tables
  before the users exist (CodeRabbit on [#196](https://github.com/projects4me/gaia/pull/196), [`db/seeds/translations.sql`](../../../db/seeds/translations.sql)).
- Run any new validation rule against the existing fixtures and seeds (4075: new checks rejected the fixture data).
- A unique-key fatal on a re-run usually means leftover soft-deleted rows. Re-run `prepare-test-db.sh` and compare
  with the baseline before blaming the diff (4075).
- The api-tester can't send multipart. Seed upload rows and commit the file under `T/fixtures/files/` (4106, [#199](https://github.com/projects4me/gaia/pull/199)).
- Run `prepare-test-db.sh` from the host. A Windows temp path inside a container fails `pg_dump` (4017).
