# Bundle H. Schema and migration infrastructure

> Generated by `gaia-dev docs generate` from docs/dev/bundles.md. Do not edit.

<a id="overview"></a>
## Overview

Gaia has no migration files. The schema is derived from metadata by [`core/libs/meta/migration.php`](../../../core/libs/meta/migration.php) and
[`core/mvc/db/migration/Postgres.php`](../../../core/mvc/db/migration/Postgres.php). This bundle covers changes to that machinery or data fixes that metadata alone
can't express.

<a id="exemplars"></a>
## Exemplars

- [#192](https://github.com/projects4me/gaia/pull/192): `Postgres.php` keeps `issues.status` in step on rename.
- [#193](https://github.com/projects4me/gaia/pull/193): multi-column unique indexes.
- [#162](https://github.com/projects4me/gaia/pull/162): the issue-number sequence.

<a id="touchpoints-in-order"></a>
## Touchpoints, in order

1. [`core/libs/meta/migration.php`](../../../core/libs/meta/migration.php) or [`core/mvc/db/migration/Postgres.php`](../../../core/mvc/db/migration/Postgres.php).
2. The metadata that uses the new capability.
3. The harness, when the test DB needs it (`prepare-test-db.sh`).
4. `client.json` cases.
